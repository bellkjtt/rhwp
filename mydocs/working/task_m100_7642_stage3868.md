## #1950의 독립 PDF와 테스트 기대값

입력은 `samples/issue1950_hwp3_tab_charoffset.hwp`다. 저장소 원장
`tests/fixtures/oracle_page_count_baseline.tsv`는 독립 PDF 1쪽·기존 출력 1쪽을
기록한다. 기존 검사 코드는 이 입력을 실제로 열어 `DocumentCore::page_count()`와
대조한다. 골든 SVG나 고정 px 좌표를 비교하는 검사가 아니다.

독립 PDF는 다음 두 파일이며 모두 같은 문서의 1쪽 출력이다.

- `pdf/issue1950_hwp3_tab_charoffset-hwp-2020.pdf`
- `pdf/issue1950_hwp3_tab_charoffset-2024.pdf`

첫 파일의 Creator는 Hwp 2022이며 두 번째는 Hwp 2024다. 파일명이나 Creator만으로
새 MCP Print 이력을 주장하지 않는다. 이 단계에서 새 MCP 출력은 하지 않았다.
기존 PDF의 텍스트와 좌표를 독립적으로 읽은 결과, 두 파일 모두 표 뒤 보고 문장,
서명, 마지막 `2 - 48`, 아래쪽 `- 581-35 -`를 같은 첫 쪽에 보존한다.
비교한 마지막 10개 span의 내용·좌표도 서로 같다. 파일별 SHA와 전체 span은
`stage3866-issue1950-independent-pdf-audit/receipt.json`에 보존했다.

## 같은 글꼴 조건의 새 Native/fresh WASM 검증

전체 Rust 종료 후 사용자 지시에 따라 Windows 원본 `gulim.ttc`를 시스템에 등록했다.
설치 대상은 `/usr/local/share/fonts/windows-system/gulim.ttc`이며 원본과 설치본의
SHA-256은 `4b9ac63e8920ed1bae29c068025ed30493464c18ee18617887daa18e59189226`로 같다.
돋움·돋움체·굴림·굴림체의 실제 시스템 매칭을 확인했다. 등록 전 검증 결과를 새
글꼴 조건의 결과로 재사용하지 않고 base와 후보를 모두 다시 출력했다.

`stage3865-issue1950-{base,head}-{native,wasm}/`의 새 렌더와 96dpi PDFium 결과다.
공급 글꼴 경로와 출력 프로필을 동일하게 유지했다.

후보의 수치는 대응 가능한 첫 쪽만 비교한 진단값이다. 둘째 쪽에는 독립 PDF의

직접 판독했다. 첫 쪽에서 사라진 `2 - 48`은 overlay에 PDF 전용 빨강으로 표시된다.

`- 581-35 -`는 별도 꼬리말 소속이므로 이 본문의 누락을 대신하지 않는다.
증적은 `stage3867-issue1950-panels/`에 보존했다.

## 판정과 다음 구현 범위

**실제 회귀 검출은 충족, 현재 출력의 정상 조판은 미충족**이다. 기존 1쪽 기대값은
독립 출력과 일치한다. 기준선을 2쪽으로 바꾸거나 이 입력의 회귀 검사를 제거하지 않는다.
단, 쪽수 일치만으로 전체 내용의 위치·보존까지 증명되는 것은 아니다. 구현 보정 후에는
표 뒤 보고 문장·서명·마지막 본문을 같은 쪽에 보존하는 관계도 함께 확인해야 한다.

`dump-pages`를 비교하면 후보의 표 호스트 문단 3은 저장 줄간격 500 HWPUNIT를
보존하며, base는 이 값을 0으로 처리한다. 뒤 문단의 저장 vpos도 500만큼 다르다.
표 실물 bbox는 같고 첫 쪽의 측정 사용 높이와 실제 paint 점유에는 차이가 있다.
원본 줄간격을 제거하거나 특정 문서의 쪽수를 강제하는 보정은 하지 않는다.
측정·쪽 나눔·실제 배치가 표 뒤 흐름 높이를 소비하는 경로를 먼저 추적해야 한다.
이 단계는 그 원인 구현을 완료했다는 보고가 아니다.

원래 시험지 전체, 수식 원본, 나머지 실패·lint·Studio·유입 PR 기능 보존 검증은
여전히 남아 있다. 이 문서의 단일 입력 검증으로 PR 준비 완료를 선언하지 않는다.
