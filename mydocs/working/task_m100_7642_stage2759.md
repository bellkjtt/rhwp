## 자동 줄 캐시의 적용 전제 보정

CLI `dump --section 1 --para 216`으로 원본 두 형식을 직접 읽었다.
둘 다 52자·control 0개·같은 물리 폭·문단 정렬·번호와 글자 크기/장평이지만,
저장 둘째 줄의 문자 시작은 HWP 48, HWPX 50이다. 독립 Print는 두 형식 모두
해당 질문을 한 줄로 출력한다. 어절이 중간에서 잘렸는지로 캐시의 유효성을
판단한 조건이 한 형식의 같은 문제를 빠뜨렸다.

본문 정규화는 `project_stored_soft_wraps`로 같은 실제 frame의 자동 줄을
재검토한다. 새로운 줄 수·공백과 동일 프레임의 후속 원점을 함께 발행하는
생산/소비 경로는 유지한다. 명시 개행·실제 쪽/단 경계·개체 제어·외부 배제·
구현 생성 줄은 계속 거절한다. 빈 문단과 마지막 빈 예약 행은 기존 점유를
보존한다. 문서 ID나 질문 문자열·문자 위치 상수를 구현 조건으로 쓰지 않는다.

본문 전체 후속 축을 소유하지 않는 지역 셀/그림의 기존
`can_rejoin_stored_word_tail`은 어절 꼬리 계약을 유지하고 같은 frame 투영을
호출한다. 본문 적용 범위를 별도 지역 높이 추측으로 복제하지 않는다.

## PostScript 프로그램과 family fallback 구분

명시 원본 family·그 설치 별칭/굵기 해소 목록을 생성 fallback과 구별해
본문/수식의 공통 후보 구성에 전달한다. 알려진 system family는 같은 방식으로
조회한다. 원본이 명시한 ID 6은 계속 프로그램으로 찾으며, 시스템 색인이
생성 fallback 때문에 초기화되는 경로를 제거했다. custom/system/bundled의
순서와 같은 family의 문자별 fallback은 유지한다. 없는 이름을 OS에 직접
질의하는 headless CoreText 경로는 추가하지 않았다.

OpenType name ID 6의 ASCII 문자 제약에 맞지 않는 이름은 PostScript 색인을
열지 않는다. 이 검사는 일반 family 이름 수용과 별개다. 길이 상한은 추가하지
않았다. 새 작은 unit은 사양상 불가능한 요청에서 시스템 색인을 열지 않는
경계 계약이며, 실물 화면이나 픽셀 기대값을 추가한 검사가 아니다.
