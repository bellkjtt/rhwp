# #7642 확정 저장 원점과 임시 로컬 원점 구분

## 실행으로 확인한 새 회귀

`stage3465`의 전 103문서 Native 검사에서 온새미로 HWP/HWPX가 각각
46쪽에서 47쪽으로 늘었다. 같은 원본·독립 Print·이전 `7d685cc178`은 모두 46쪽이다.
최초 소속 차이는 두 형식 모두 41쪽, 구역 3의 문단 115 마지막 줄이다.
독립 Print는 그 줄을 41쪽에 둔다. 앞쪽의 출력은 같은 상태다.

원본은 마지막 줄에 vpos=0을 기록했지만 현재 쪽은 앞 문단의 저장 프레임 중간에서
시작한다. `stage3483`의 실제 호출 로그는 `page_base=None`, `lazy_base=Some(1800)`,
`dirty=true`를 보여 준다. 문단의 실제 top 801.97333px가 저장 top에서 1800HU를
뺀 값과 같다는 것만으로 원래의 물리 쪽 경계까지 유효하다고 승격했다.

반면 보정해야 했던 sample4 문단 338은 `page_base=Some(0)`, `lazy_base=None`,
`dirty=true`이고 저장·실제 top이 모두 854.4px다. 현재 저장 프레임이 확정된 이
사례는 앞선 dirty 이력만으로 거절하면 본문 아래로 글자가 나간다.

## 공통 계약과 변경 범위

페이지의 원점을 첫 항목에서 임시로 유추한 값과 확정된 저장 프레임 값으로 구분한다.
재조판 이력이 있는 쪽에서 reset의 물리 소유를 다시 입증하려면 현재 사용하는 축이
확정 저장 원점과 같아야 한다. 그 위에 기존의 현재 문단 비편집·실제 앵커·연속 prefix·
본문 안의 마지막 점유·유효 reset 검사를 그대로 적용한다.

`TypesetState.vpos_page_base` 생산 → `LineScanPage` 읽기 전용 관측 →
`stored_body_reset_fragment_matches_current_flow`의 공통 소유 판정 →
전체 문단의 강제 경계와 분할 줄 수용 양쪽이 같은 판정을 소비한다.
새 문서명·좌표 문턱·기대 쪽수 분기를 추가하지 않는다.

독립 원본·Print와 새 전쪽 검증이 계속 필요하다. 구현 뒤 중간공한 프로그램 폭 보완과
같이 빌드하고 sample4·온새미로 양쪽, 앞선 표 예산 검사와 103개 전체 범위를 확인한다.
