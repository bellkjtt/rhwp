# #7642 Stage 172 — 그리스 이름의 대문자 철자와 수식 원문 대응

Issue: #7642

## 독립 근거와 원인

Stage 171 카탈로그 2쪽에서 `ALPHA over BETA`는 Native의 라틴 문자 이름과
한컴의 대문자 그리스 기호가 다르다. 이를 문서 위치나 특정 식의 예외로
처리하지 않는다. 24개 그리스 이름의 소문자·첫 글자 대문자·전체 대문자,
혼합 대소문자와 붙여 쓴 피연산자까지 80개를 독립 재생성·Print했다.
입력은 `pdf/issue7642-extended-base-script-diagnostic/extended-base-script-input-v8.hwpx`,
그 저장 HWP와 Print PDF는 같은 폴더의 `*-v8-2024.*`다.

저장 job: `b37549b5-cf7c-4e40-84d0-81afe9a49813`.
Print job: `539576d6-00e6-44cd-b80e-da6b8910924c`.
HWP SHA-256: `a4aad0d666baf4a35969808eb22767cca311592d351cc5ddc9d73fdd95603033`.
PDF SHA-256: `678e30a454bcc8ba4ca2d13afcc6a52d314ea5932baa063f8cbf2c33aaad0df5`.
실제 한컴 13.0.0.3901, engine 2024, Print method 0,
`frame_print_to_pdf_ex_one_up`이며 전체 두 쪽이다.

수정 전 Native/fresh WASM은 두 쪽 모두 미달이며 최저 87.48741%다.
전체 대문자의 기호와 붙여 쓴 피연산자를 읽지 못한다. 반면 `AlPhA`,
`aLpHa`는 독립 Print에서도 문자 이름으로 출력된다. 임의 혼합 대소문자를
그리스 기호로 접지 않는다. 무조건 대소문자를 무시하는 방식은 반례에 어긋난다.

## 생산·소비와 적용 경계

`symbols::lookup_symbol` → tokenizer의 `is_greek_command`·최장 안전 접두사 →
parser 기호 AST → LayoutBox·공통 글꼴 전진폭 → Native/WASM 실제 표시로 이어진다.
현재 기호표는 소문자와 첫 글자 대문자만 조회한다. 전체 대문자 이름은
Text로 남고, 안전 접두사 판정도 실패해 `ALPHAX`를 A와 X로 분리하지 못한다.
기호 조회에서 정상 대문자 이름의 전체 대문자 철자를 함께 수용하면 두 소비
경로가 같은 결과를 사용한다. 문서 ID, 수식 문자열, 고정 화면 좌표의 예외를
넣지 않는다. 소문자·첫 글자 대문자·혼합 철자·일반 식별자와 다른 기호의
기존 의미는 보존한다.

Native는 80개 전체 두 쪽과 카탈로그·원본 영향을 확인하고, 방향이 맞으면
fresh WASM을 빌드한다. 새 정식 회귀는 독립 Print와 Native/fresh WASM 전체
90% 이상 및 확대 판독 뒤 별도 이름으로 추가한다. 기존 golden 자동 갱신과
임계값 완화는 하지 않는다.

## 나머지 회귀 실패의 입력 전제

#6597의 합성 입력은 `CharShape::default()`의 `base_size=0`을 저장한다.
현재 기본값의 0은 글꼴 정보 없음/숨김의 기존 계약이며 줄 폭 수집이 빈 결과로
끝나는 원인을 먼저 구분한다. 글꼴 크기를 기본값에서 몰래 늘리지 않는다.
실제 원본의 독립 13쪽 대조와 유효한 글꼴 크기의 최소 입력을 확인한 뒤
새 관계형 검사로 다룬다. 테스트 셋업 오류를 실제 출력 결함이나 통과로
보고하지 않는다. 기존 56건 전체 해결·최종 PR 검증은 아직 미완료다.
