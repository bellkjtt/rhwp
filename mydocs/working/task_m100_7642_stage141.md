## 범위와 기준

`bfa28a77a2714482f647ee6a7b9aa7f7876d8404`를 고정한다. 이전 goal turn은
진단 원본 보존·커밋·devel rebase 및 실제 Native/WASM lint로 진전했다.

## 순차 검증과 실행 경계

1. 현재 source의 workspace build와 workspace/all-target Clippy를 공용 target에서 순차 확인한다.
2. 같은 source의 Native release-test 바이너리를 고정하고 영향을 받은
   11월 HWP/HWPX의 21~22쪽 및 전체 쪽수를 독립 Print와 대조한다.
3. 큰 컷 차이가 없으면 fresh WASM을 같은 target에서 순차 빌드하고
   루트 pkg·Studio public·고정 검증 package의 해시를 확인한다.
4. 두 backend의 전체 원본 TSV와 변경 경계·사용자 지적 영역 review/overlay를 확인한다.
   한 페이지라도 90% 미만·측정 불가·쪽수 불일치면 원인을 먼저 수정한다.
5. 새 관계형 검사와 이전 전체 nextest 실패 원본을 새 head에서 확인한다.
   px·해시 기준을 통과 목적으로 완화하지 않는다. 이관된 옛 파일은 되살리지 않는다.

기존 stage138 큐의 81개 완료를 현재 source 결과로 사용하지 않는다.
새 source 파일 목록을 다시 읽어 빌드 provenance의 해시 범위도 갱신한다.
