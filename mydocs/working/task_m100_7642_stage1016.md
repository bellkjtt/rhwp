# 단계 1016 기준 영역보다 넓은 부동 표의 가로 정렬

Issue: #7642.

## 독립 근거와 원인 경로

원본 `samples/exam_math_no.hwp` 첫 쪽의 머리말 표는 너비 66,699HU, 본문 영역은 약 66,330HU다. 표는 글자처럼 취급하지 않고 쪽 본문 기준 가운데 정렬, 가로 오프셋 0이다. Native 표 왼끝은 71.8px인데 독립 한컴 Print PDF의 실제 밑줄은 51.959999pt(96dpi에서 69.28px)에서 시작한다. 제목 글자 간 전진은 두 출력이 거의 같지만 같은 표 안의 제목·밑줄이 함께 약 2.5px 오른쪽으로 밀렸다. 단계1015의 원본 dump, 공개 layout 진단, PDF 실제 drawing/문자 위치를 보존한다. 문제를 특정 제목·문서·픽셀 오프셋으로 보정하지 않는다.

원인 경로는 원본 표의 가로 기준/정렬/너비 → `compute_table_x_position`의 depth0 비-TAC 분기 → `table_x` → 셀·제목·밑줄이다. `(기준 너비 − 표 너비).max(0)`이 가운데 정렬의 음수 여백을 잘못 없앴다. `float_placement::horizontal_range`도 같은 제한으로 빈 host의 흐름 범위를 계산한다. 두 소비 지점에서 같은 정렬 함수를 사용해 실제 가로 범위를 공유한다. `table_x` 뒤의 왼쪽 캡션 이동은 기존 계약대로 보존하며, 원본 머리말에는 캡션이 없다. 이미 확정된 inline/물리 원점은 다시 정렬하지 않는다.

중앙 정렬은 기준 영역과 개체의 중점이 같아야 하고 오른쪽 정렬은 두 우단이 같아야 한다. 개체가 더 넓어도 이 관계가 유지돼야 한다. 왼쪽/안쪽 정렬과 원래 signed offset은 보존한다. 본문에 참여하는 TAC의 줄 구성과 중첩 표의 셀 안 수용 규칙은 이 단계의 변경 경로가 아니다. 넓은 부동 표를 줄이거나 자르지 않고 원본 폭과 내용 순서를 유지한다.

## 구현·검증 계획

공통 정렬 함수를 작은 모듈로 만들고 위 두 소비 지점에 연결한다. Native 실제 첫 쪽에서 독립 PDF와 제목·밑줄을 다시 대조하고 math_no 전체 20쪽 Native/fresh WASM TSV를 산출한다. 같은 helper의 적용 경계인 폭이 작은/같은/큰 부동 표, 가운데/오른쪽/왼쪽, signed offset은 정렬 관계로 확인한다. 합성 source 계약은 실제 공개 문서/레이아웃 경로를 통해 확인하며 실물 출력의 90% 통과로 대체하지 않는다. 전쪽 미달이면 실물 문서의 새 회귀 추가와 기존 기대값 갱신을 보류한다. 원본 55문서와 대조군의 최종 head 검증·base 하락 비교·전체 회귀·lint·release WASM은 계속 필요하다.
