## 원본·독립 출력·생산 결과의 연결

원본 문단 441은 저장 줄 8개다. 모두 `column_start=22800`, `segment_width=28224`, 끝 `51024HU`로 본문 오른쪽 변을 공유한다. 앞 문단 440의 실제 그림은 Paper/Paper 기준 Square, 크기 21356HU, 좌우 바깥여백 각각 852HU다. 그 그림의 흐름 폭 **23060HU**가 원본에서 제외한 폭 **22800HU**를 설명한다. source LineSeg·picture 속성은 원본을 파싱한 진단 직렬화에서만 확인했으며, 그 HWPX를 기준 PDF나 검증 입력으로 교체하지 않았다.

`원본 8개 줄 → composition → recompose_stored_lines_in_frame_with_known_square_band → resolve_stored_line_segs_in_frame → stored_rows_require_external_geometry → 측정용 format/실제 layout_partial_paragraph`를 추적했다. 외부 개체 증거 helper의 균일 lane 판정이 **lane 시작이 프레임 왼쪽 변과 같을 때만** 폭 결손을 계산한다. 그림이 왼쪽에 있고 lane이 오른쪽 변을 공유하면 원래 줄의 소유를 놓친다.

현재의 전폭 프레임이 문단을 재분할하고, 후단 layout은 저장 `column_start/segment_width`를 다시 적용한다. 실제 첫 4개 줄의 자식 run 끝은 페이지 오른쪽을 약 200px 넘으며, 공개 render tree의 줄 박스는 376.32px인데 자식은 636px까지다. 공통 helper 뒤의 배치 원점 재선택까지 확인했다. 글자를 가리거나 bbox만 clamp하여 해결하지 않는다.

## 보정 규칙과 반례

균일 lane이 본문 프레임 안에 있고 **왼쪽 또는 오른쪽 한 변을 공유**하면, 제외 폭은 `프레임 전체 폭 - lane 폭`으로 계산한다. 모든 저장 행의 시작·폭도 같아야 한다. 같은 세로 band의 실제 개체가 그 폭을 설명할 때만 프레임이 계산할 수 없는 외부 기하로 남긴다. 기존 오른쪽 개체/왼쪽 lane 계약을 대칭으로 확장한다. 문서명·문단 번호·고정 px·새 허용치에 의존하지 않는다.

개체 없는 일반 들여쓰기, 같은 폭이지만 다른 세로 band의 개체, 양쪽이 모두 안으로 들어간 lane, 프레임 밖/비정상 폭을 반례로 대조한다. 측정과 실제 배치가 같은 helper 결과로 저장 8개 줄을 소비하는지 실행한다. 이 변경은 편집 여부 판정이나 저장 정보의 유효성 검사를 추가하지 않는다. 재조판·편집 경로의 기존 처리는 호출 경로와 실행 대조군에서 별도로 확인한다. 저장 원점 판별 helper는 1000줄 미만의 별도 모듈로 옮겨 공통 조건을 확인하기 쉽게 한다.
