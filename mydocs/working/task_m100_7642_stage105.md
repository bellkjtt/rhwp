# Stage 105 — 독립 Print의 장식 첨자 범위와 최신 backend

Issue: #7642. 원본 55개·853쪽과 회귀 292개·#1139 전체 관계형 전환 목표를 유지한다.

## 최신 기준과 보존

`upstream/devel`의 `21ed64071` 위로 기존 372개 커밋의 리베이스를 완료했다.
리베이스 직후 head는 `479e34b85`이며 upstream 대비 behind 0이다. 이전 브랜치는
`backup/equation-before-upstream-20261011-stage104`에 보존했다. Native `f9c6841fb`의
frozen 결과는 이전 source의 증거로 유지하며 리베이스 후 결과로 승격하지 않는다.

충돌에서는 Studio의 기본 font bytes와 math fallback을 모두 보존했다. Skia의
`EquationFonts`를 문자별 face 선택·별도 글꼴·늘인 괄호·BOX·부정 빗금·분수 축에
전달했다. 추출 glyph module에도 같은 자원을 전달한다. 실제 lint/typecheck·출력
확인은 아직 남아 있다. upstream backend 검증 가이드의 소비 경로도 함께 따른다.

## Print 확대가 바꾼 해석

독립 Print의 `vec {OP}^2`는 화살표가 OP와 위첨자를 함께 덮는다. 기존의 외부
첨자 해석은 틀렸으므로 완성된 인자의 후행 첨자를 먼저 소비한 뒤 장식을 감싸는
경로를 확인한다. `vec {x^2}`의 내부 첨자와 명시적으로 장식 자체를 다시 묶은
`{vec {OP}}^2`를 구별하고, 부모 첨자 슬롯의 `attach_scripts=false`는 유지한다.

Stage 103의 크기별 1230/1538/2228/3023HU 프레임은 위 입력의 독립 측정값이다.
이를 외부 위첨자 프레임으로 분류한 것도 철회하며 장식 안의 단일 위첨자 경로에
귀속한다. 독립 자료 없이 추가한 외부 장식의 uppercase gap/shift/프레임 분기는
제거한다. 일반 대문자 본체의 기존 0.15em 여유·독립 글줄 shift는 유지한다.

## 묶음 검증

실제 AST → 인자 위첨자의 글자 원점·전진 → 장식의 전체 본체 폭·상단 → 공통
논리 프레임 → 저장 줄의 점유/paint 원점 → SVG/Skia/Canvas2D/CanvasKit 소비를
추적한다. 먼저 현재 parser 소유 진단과 순차 lint/typecheck·Native 진단 16개·실제
원본 20쪽의 새 확대를 확인한다. 전쪽 점수와 확대 미달을 별도로 기록한다.
Native/fresh WASM 전쪽 TSV와 확대를 충족한 뒤 관계형 회귀를 변경한다.
진단·TSV·nextrun은 ignored output에 보존한다. 전체 회귀와 PR/CI/후속은 미완료다.
