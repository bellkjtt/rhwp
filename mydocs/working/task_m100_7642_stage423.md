# Stage 423 — 단자리 네모 숫자의 공통 em 기하

## 독립 근거와 범위

원본·독립 Print·해시는 앞 단계 `task_m100_7642_stage412.md`를 따른다.
전진 보정 뒤 Native/fresh WASM 전 5쪽의 영월 최저는 99.29000%, 항만은
97.76951%다. 두 빌드·Studio 동기화·입력/쪽수는 Source413/414 영수증에서 확인했다.
현재 항만 확대에서는 합성 상자와 숫자가 작은 결함이 남는다.

0..9의 Haansoft Batang PUA는 같은 바깥/안쪽 사각 경계를 가진다.
UPM 1024의 바깥 경계는 (52,-71)-(971,842), 안쪽은 (78,-45)-(945,817)이다.
현재 0.72em 정사각형과 0.5em 숫자는 이 경계를 반영하지 않는다.
일반 숫자에서 네모 숫자의 내부 잉크 경계로 투영할 상대 메트릭은
`stage418-single-digit-synthesis-metrics.json`에 보존한다. 사유 글꼴 바이트나
윤곽선을 코드에 복사하지 않는다. 실제 일반 숫자는 공급된 Haansoft Batang을
우선 사용한다. 조사한 OFL Batang에는 필요한 PUA cmap가 없어 새 폰트를 추가하지 않는다.

일반 숫자의 윤곽과 PUA 내부 윤곽은 완전히 같지 않다. 곡선 표본 대조에서
20pt 기준 최대 약 0.81px 차이를 관측했다. 이는 진단이고 완료 판정이 아니다.
보정 뒤 독립 Print와 실제 확대 PNG에서 형상·미세 간격을 다시 판독한다.
다자리 PUA에는 부분 글리프도 있어 단자리 메트릭을 자동 적용하지 않는다.
기존 다자리 의미·처리는 별도의 독립 자료 없이 변경하지 않는다.

## 공통 결과와 실제 소비

`boxed_digit_geometry::single_digit`가 동일 font size에서 프레임 중심선·획·
일반 숫자의 x/y 스케일과 원점을 산출한다. 특정 문서나 셀 좌표를 조건으로 쓰지 않는다.
SVG·Canvas2D·Native Skia는 기존 공통 글자 전진 위치와 baseline에 이 결과를 적용한다.
CanvasKit은 같은 데이터·투영식을 사용하며 수정한 실제 소비 경로를 함께 확인한다.
다른 paint 효과·CharOverlap의 경로는 기존 단자리 평문 소비와 구분해 대조한다.

## 검증 계획

모든 Cargo 빌드는 공용 `target/pr-review`, 빌드잡 8개로 순차 실행한다.
Native/fresh WASM 전 5쪽과 항만의 숫자·네모·하이픈을 같은 원점에서 확대 비교한다.
Native PNG/Canvas2D/CanvasKit의 해당 표시도 대조하고 형상 차이가 남으면 추가 보정한다.
독립 Print와 전쪽 90%·직접 판독 후 #6127/#6172의 고정 px 검사를 새 이름의
소유·순서·포함·전진 관계 검사로 교체한다. 두 입력은 SHA-256이 같지만
서로 다른 원본 파일 참조는 보존한다.

전체 55문서·853쪽 및 나머지 실패 검사의 완료를 이 단계의 통과로 대신하지 않는다.
Source393 정상 대조군 14문서·89쪽은 Native/fresh WASM 모두 최저 91.99347% 이상이며
2023년 9월 HWP/HWPX 전 40쪽도 양쪽에서 최저 96.76660%/96.79178%다.
이는 앞 source의 증거다. 이후 조판 변경에 영향을 받는 범위는 재출력한다.
