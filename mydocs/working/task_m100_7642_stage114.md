# Stage 114 — 언어 기출 도형 리사이즈의 관계형 회귀 준비

Issue: #7642. 전체 검증과 회귀 전환 범위를 유지하며 새 검사를 아직 적용하지 않았다.

## 원본과 편집 경로의 근거

`samples/21_언어_기출_편집가능본.hwp`는 15쪽이며 수식 컨트롤이 없다.
검증 소스 `a4454ac384f12bffe95eaec8356cefe2a63dda4c`의 원본 전쪽 Native·fresh WASM
최저값은 각각 95.16239%다. 이는 진행 중인 전체 스윕의 해당 원본 완료 결과이며
이후 코드 소스의 재검증이나 전체 원본의 완료를 뜻하지 않는다.

실제 편집 대상은 원본 소유 `s0p4c0`의 가로선이다. 선언 크기는 31,804×4 HU,
생성 시 크기는 100×100 HU다. 공개 WASM setter로 폭만 15,902 HU로 바꾸고
다시 31,804 HU로 되돌렸다. 세 상태는 모두 15쪽이다. 저장본의 orgSz는 세 상태
모두 100×100으로 보존되고 curSz만 선언 크기를 따라간다. getter의 값과 HWPX
직접 속성을 각각 확인했다. 모델 속성 보존만으로 실제 선 표시의 정확성을 판정하지 않는다.

세 저장본의 독립 한컴 2020 Print는 다음과 같다.

| 상태 | Print job |
| --- | --- |
| 편집 전 저장본 | `d1c948a3-1eae-4fbc-83a6-a292d7a62069` |
| 절반 폭 저장본 | `820f8eab-3ab3-4c7c-9817-f2aa70db786c` |
| 되돌린 저장본 | `2412520a-b3f7-4616-9932-5f2b6908e93c` |

모두 PrintMethod 0·한컴 2020 1-up PDF driver 계약을 확인했다.
새 보정 소스 `86e4697b96d5bfacb0784839b742c7ac5663c51d`의 Native·fresh WASM으로
원본과 세 저장본의 전쪽을 대조한다. 실제 Print는 편집 전 15쪽, 절반 폭 16쪽,
되돌리기 16쪽이다. 편집 전과 되돌리기의 HWPX SHA-256은 모두
`902a60e1fa9a18ccfaabe8efb2b0c126d318a00643f5181d2e3da669af28c687`로 동일하고
압축 패키지의 모든 항목 바이트도 같다. 그런데 첫 쪽 문자 수는 각각 2,085와
1,737로 달라 단순 빈 쪽 추가가 아니다. 용지는 두 출력 모두 841×1,190pt다.
같은 입력의 독립 Print 반복 재현을 먼저 확인하고 이 차이를 RHWP 회귀로 단정하지 않는다.

`stage114-line-resize-focused`의 초기 15쪽 가정은 실제 기준과 달라 실행 전에
중단됐다. controller 상태를 실제 종료 코드 1로 바로잡고, 쪽수 차이와 미측정을
보존하는 `stage114-line-resize-diagnostic`에서 대조를 재개한다. 같은 입력의 재출력은
`stage114-identical-input-print-repeat`에 보존한다. 기준 일관성이 확인되기 전 이
자료로 90% 통과나 관계형 회귀 적용을 선언하지 않는다. 원본 PDF와 저장본 Print도 구별한다.

## 회귀 교정안

기존 `issue_6806_shape_resize_original_scale`의 길이 선택자는 고정 y 범위
532..535로 SVG 선을 고르고 424.05px를 기대했다. 현재 원본의 실제 선은 그
영역에 없으며, 이 선택 실패를 도형 리사이즈 자체의 회귀로 바꿔 설명하지 않는다.

교정안은 실제 RenderNode의 구역·문단·컨트롤 소유로 선을 유일하게 선택한다.
표시 끝점의 가로 성분 비율이 요청 폭 비율을 따르는지, 폭만 바꿀 때 세로 성분이
보존되는지 검사한다. 비율 오차는 무차원 값이다. 되돌리기는 원본 모델 속성과
해당 선의 동적으로 관측한 끝점 복원을 검사하며 전체 SVG 문자열을 고정하지 않는다.
같은 이름의 기존 세 검사를 유지한다.

교정안은 ignored `stage114-shape-resize-relational-proposal.rs`에 보존했다.
원본·편집 저장본의 전쪽 Native/fresh WASM 90% 이상 및 실제 선의 확대 판독을
확인한 뒤 정식 테스트에 적용한다. 지금은 정식 관계형 전환이나 실행 통과로 세지 않는다.

입력·Print·getter/직접 속성·tree·명령·빌드 출처는 ignored
`output/pr-review/issue7642/failed-inputs-20261008/stage15-current-validation/`의
`stage114-line-resize-input`과 `stage114-line-resize-focused`에 있다.

## 종료된 중간 산출물 정리

종료된 소스 `a4454ac38`의 Native/WASM 반례 44개에서 SVG 112개, 약 1.973 GiB를
SHA-256 원장을 작성한 뒤 제거했다. 원본·Print·래스터·tree·TSV·빌드 provenance와
미달 결과는 보존했다. 공유 target과 실행 중인 전체 스윕의 산출물은 정리하지 않았다.
`stage113-completed-focused-svg-cleanup.json`에 정확한 제거 경로와 해시를 기록했다.

## 같은 입력 Print의 추가 재현과 원본 형식 대조

같은 HWPX를 두 번 더 출력한 Print job은
`e3b844ce-c5bf-4cd8-9fe1-d9061d7e3c09`와
`645fdfd3-1963-4a85-9078-476794ff7840`다. 출력은 다시 15쪽과 16쪽이다.
입력 바이트가 같은 네 출력의 쪽수 차이는 재현됐으며, 문서 구현을 16쪽에
강제로 맞출 근거가 아니다. 첫 15쪽 저장본도 Native 최저 69.84243%로 미달이다.
같은 원본 HWP는 독립 Print 대조 95.16239%이므로 원본과 HWPX 재저장 출력의
계약을 구별한다. 이 미달 결과를 지우거나 회귀 기대값을 완화하지 않는다.

기존 세 회귀는 원본 HWP의 도형 편집 계약을 검사한다. 같은 setter의 전·후·
되돌리기 상태를 원본 형식 HWP로도 저장하고 독립 Print를 산출 중이다.
HWPX 미달을 HWP 통과로 바꾸어 보고하지 않고 각 저장 형식의 입력·Print·쪽수와
시각 결과를 따로 보존한다. 정식 관계형 검사 적용은 해당 편집 경로의 실제
출력과 독립 기대값이 확인된 뒤 진행한다. 새 입력과 변환 기록은
`stage114-line-resize-hwp-input`에 있다.
