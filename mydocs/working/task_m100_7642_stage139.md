# 전체 회귀 실패 원본의 일괄 분석과 관계형 검사 준비

- Issue: #7642, Refs #7445
- 검증 production: `015764c13c99ad3694b35ee57411728f83cb6579`
- 단계 시작 head: `40ddcd07b9600795a9f640b52fe907b09a3d95b4`
- 목표 55개 원본·853쪽의 Native/fresh WASM 전쪽 검증과 새 이름의 관계형 회귀를 계속한다. 아래 분석을 전체 검증 완료로 해석하지 않는다.

## 이번 실행에서 확인한 사항

전체 nextest는 컴파일을 마치고 실제 10,246개 검사를 실행 중이다. 출력이 없는 빌드나 오래 걸리는 검사를 중단하지 않았고 동일 controller의 실제 프로세스를 확인했다. 전체 종료 후 최종 실패 집합·exit code로 판정한다. Rust source와 test는 실행 중 수정하지 않는다.

현재 실패에서 원본·의도된 계약·검사 선택 방식·독립 PDF를 함께 모으고 있다. 검사마다 하나씩 빌드하지 않고 근거 확보와 변경을 모아 검증한다. 기존 px 선택, 단일 TextRun 분절, 정확한 정상 소유, 실제 구현 결함, CLI·serializer 동작과 golden을 구분한다. 실패를 현재 baseline으로 덮거나 미검증 문서를 시각 통과로 올리지 않는다.

### 이관 문서의 동일 바이트 별칭

#7749는 규제영향분석 HWPX의 두 경로가 동일 원본임을 기록한다. 실제 두 입력의 SHA-256을 다시 확인해 모두 `e7b147f7cea66c97bed79085a3d89c2656037e0f711232f659ed3c7344984f62`임을 확인했다.

- `samples/issue3637/regulatory_impact_nested_table_escape.hwpx`
- `samples/issue6697/80550-agricultural-machinery-act-amendment.hwpx`

현재 본문 넘침은 두 경로를 분리하지만 텍스트 겹침·용지 밖은 첫 경로만 제외한다. 그래서 이미 이관한 같은 원본의 다른 파일명이 겹침 원장에 남아 14→16으로 실패했다. 전체 실행 뒤 같은 원본의 이관된 text/off 축에 별칭을 포함하고 해당 기준 행을 제거한다. 정상 parser·IR·serializer 계약과 원본/PDF는 유지한다. 쪽수·다른 축으로 이관 범위를 확대하지 않는다. 이 변경은 피델리티 개선이 아니다.

### 새 겹침 실패 두 원본

`stored_vpos_rewind_form.hwp`의 독립 기준은 cairo PDF가 아닌 `pdf/issue3837/stored_vpos_rewind_form-hwp-2020.pdf`다. Hwp 2022 / Hancom PDF의 전4쪽이며, 같은 production의 Native/fresh WASM 전4쪽 모두 최저 **96.26357%**다. 이는 겹침 증가의 자동 점검을 면제하지 않는다. 해당 사건의 문단·줄·개체 소유와 독립 PDF의 실제 교차를 추가 판독한다.

`hwp-multi-001.hwp`의 기준은 `pdf/hwp-multi-001-2022.pdf`의 전9쪽이다. 원본 `printMethod=4`를 확인해 실제 기준의 용지·배율·쪽수를 함께 대조한다. Native 최저 **96.38192%**, fresh WASM은 진행 중이며 종료 결과로 확인한다. 전체 raster 톤·기호 차이와 한 건의 겹침 증가를 평균값으로 숨기지 않는다.

### 헤더 사각형의 독립 저장·Print 대조군

기존 `header_paper_relative_shape_uses_page_origin`은 합성 사각형의 PAPER 오프셋을 물리 용지 원점에 더하는 기대를 고정한다. 그림의 Print 근거를 도형의 증거로 대신하지 않고 같은 속성의 실제 사각형 대조군을 별도로 만들었다.

진단 생성기는 기존 `pic-in-head-02.hwp`의 구조를 HWPX로 내보낸 뒤 본문 한 문단·헤더 사각형만 남긴다. 정상 HWPX의 rectangle 구문, Header/colPr의 `hp:ctrl` 포장과 XML namespace·자식 순서를 사용한다. 한컴 engine2020으로 HWP 저장한 뒤 그 저장본을 같은 engine의 Print로 출력했다. 첫 시도는 잘못된 포장 때문에 헤더가 저장되지 않아 자동100%여도 부적합으로 보존했다. 이 실패를 정상 생성본의 증거로 쓰지 않는다.

두 번째 저장본에서 Header와 Rectangle을 실제 확인했다. job `e1f4c46c-0963-46ba-abb3-8f52b8b80725`가 HWP 저장본을 생성했고 후속 Print job은 `stage139-header-origin/v2/print-status.json`에 보존한다. 실제 한컴 `11.0.0.9136`, `pdf_print_method=0`, `pdf_output_mode=hancom2020_pdf_driver_one_up`, 전체1쪽이다. Native/fresh WASM 전1쪽은 모두 **100.00000%**, 1/1쪽이며 전체 영역과 같은 사각형을 직접 확대해 확인했다.

실제 사각형은 헤더 원점에서 원본의 가로/세로 오프셋만큼 이동한다. Print와 Native/fresh WASM의 위치·너비·높이·본문 앞 소속이 대응한다. 최종 새 검사는 사각형을 헤더 소유로 선택하고 원본 HWPUNIT 오프셋과 헤더 프레임의 정규화 관계, 본문 전 순서·누락/중복을 검사한다. 물리 화면의 절대 px를 기대값으로 고정하지 않는다. 정상 저장본·Print PDF·대표 PNG를 정식 fixture로 보존하고 기존 잘못된 검사 원문도 보존한 뒤 새 파일/이름으로 실행한다.

## 다음 변경·검증 묶음

1. 실제 전체 nextest 종료 결과에서 실패 원본과 이관 취소/정상 계약을 대조한다. #7804처럼 이관 판정을 취소한 정상 문서의 검사는 제거하지 않는다.
2. 같은 production의 관련 전체 Native/fresh WASM 90% 이상과 직접 판독을 확보한 범위만 새 이름의 관계형 검사로 전환한다. 나머지는 원본 출력부터 보정한다.
3. 표 text의 마지막 음수 자간 표시 끝과 헤더 도형의 독립 원점 계약, #7445 별칭 누락을 한 묶음으로 변경한다. 두 11월 원본의 새 컷 검사는 전22쪽 Native/fresh WASM 완료 뒤 활성화한다.
4. source 변경 뒤 suite 준비·fmt·필수 Clippy3/workspace build·고정 base 정책·집중 nextest를 순차 실행한다. 실제 runtime 변경은 같은 공용 target에서 새 Native/fresh WASM을 빌드하고 영향 시각 결과도 재산출한다.
5. 전체 목표 입력과 현재 실패 목록의 남은 범위를 추적하고, 회귀·Native Skia·Studio·PR/CI·후속 절차를 실제 완료 증거로 판정한다.

실행 로그·TSV·중간 JSON·초안·nextrun은 ignored `output/pr-review/issue7642/failed-inputs-20261008/stage15-current-validation/`에 둔다. 이 단계의 정식 회귀·별칭 제거는 아직 실행 중인 전체 nextest 종료를 기다리며 적용 전이다.
