# #7642 직접 등록 메트릭 규칙의 조회 추적 ID 보존

Issue: #7642

## 발견과 원인

`8408ca43e2`의 Native Skia 글꼴 관찰자는 PrEP 3·15쪽과 #7336 HWPX 6쪽에서 실제 선택 face를 관측했다. WMF 문서 `samples/issue6866/156627451-quantum-science-press-note.hwpx` 8쪽의 전체 추적은 `generated metric ruleId mismatch for 한컴 윤고딕 230` 오류를 반환했다. 진단 harness의 unwrap이 종료 코드 101로 실패했으며, 원본 로그를 보존했다. 실제 raster 출력 실패로 혼동하지 않는다.

활성 레지스트리의 이 별칭은 `mode=direct`, `ruleId=rule.rust-metric.ygodic230-name`이다. 생성 투영도 그 ID와 대상 `Haan YGodic 230`을 정확히 보존한다. 반면 조회의 `metric_alias_provenance`는 모든 규칙을 W1 수집 후보로 가정해 해시 기반 ID를 재생성했다. 직접 등록 규칙의 유효한 ID가 다른 이름이라는 이유로 전체 조회가 실패했다.

## 변경과 경계

직접 등록 규칙은 생성된 활성 투영에서 실제 ID·선택 source/target·결정 계층·경계·무조건 선택을 확인하고 그 ID와 관계를 조회 JSON으로 전달한다. 일치하지 않으면 계속 오류를 반환한다. legacy-preservation 규칙의 기존 해시 대조는 그대로 둔다. 직접 등록 규칙의 W1 근거가 있다고 꾸미지 않고 레지스트리 경로와 `evidenceStatus=unknown`을 기록한다. 메트릭 전진폭·글꼴 선택·조판·paint는 바꾸지 않는다.

새 이름의 `issue_7642_direct_metric_rule_trace::direct_metric_alias_trace_uses_the_registered_rule_identity`는 활성 레지스트리의 직접 등록 별칭을 골라 공개 빈 문서/입력 API와 공개 조회를 실행한다. 독립 기대값은 레지스트리의 ID·대상·관계이며 좌표나 픽셀 값을 검사하지 않는다. 렌더링 fixture의 시각 일치로 승격하지 않는 조회 계약 검사다. 수정 전 `8408ca43e2` 라이브러리에서 같은 검사가 실제 ID 불일치로 실패하고 수정 후 통과하는지 확인한다.

현재 구현 후 실행 검증 전이다. 앞 수식 source `8408ca43e2`는 focused 138/138 통과 및 9개 가족 Native 74쪽 전부 90% 이상이다. PMATRIX 8쪽은 전부 raw 100%, EQALIGN 5쪽 최저는 98.04368%다. 원래 혼합 카탈로그의 49·66쪽과 손으로 바꾼 일부 중첩 대조군은 여전히 미달이며 근거 없이 baseline을 갱신하지 않는다. fresh WASM은 고정 worktree의 해당 source에서 별도로 실행 중이다.

진단·실패 로그와 보존된 `8408ca43e2` rlib는 ignored `output/pr-review/issue7642/failed-inputs-20261008/stage15-current-validation/stage3577-native-paint-font-observer/`에 있다. 수식 TSV와 그림은 `stage3558-equation-head-native`, `stage3582-equation-family-native-panels`, WASM 실행은 `stage3579-alignment-and-pile-wasm-build`에 있다. 이 조회 수정의 통과 또는 전체 PR 완료로 사용하지 않는다.
