# 단계 1128 자동 줄바꿈 구분 공백의 배분 소유 보정

Issue: #7642. 기준 devel은 `463c48cc228170b576c832591b76826116e86a49`다.

## 독립 근거와 실패

단계1093의 합성 HWPX를 같은 내용 그대로 한컴 engine2020의 Print로 출력한 6쪽 대조군을 사용한다. PDF 경로·SHA는 단계1117에 기록했다. 앞 공백 0·1·3개와 자간 0·음수의 각 쪽에서 Left/Justify의 첫 글자 원점은 같고, Justify의 가시 끝 글자는 본문 끝을 채운다. 원본은 수동 합성 입력이며 정상 한컴 저장본으로 분류하지 않는다.

단계1126의 공개 문자 경계 후보는 현재 구현에서 실제 실패했다. 원본 용지·여백 HU로 계산한 본문 너비266.6667에 비해 첫 줄 가시 전진은260.5다. 마지막 소비 구분자까지 배분 공백 수에 포함해 가시 글자 앞의 배분이 줄어드는 경로와 일치한다. 임의 목표 좌표나 문서 ID 분기를 추가하지 않는다.

## 생산·소비 경로와 보정

`compute_line_extra_spacing`의 내부 공백 수·가시 폭 → `extra_word_sp` → `emit_line_runs`의 말미 공백 회수 → `emitted_run_layout_positions`의 게시 positions → bbox·다음 런 원점으로 추적한다. 자동 줄바꿈에서 소비한 구분 공백도 원문 문자 소유와 자연 전진은 보존하지만 내부 낱말 사이 배분에는 참여하지 않는다. 마지막 음수 자간의 가시 끝 보정도 저장 줄과 같은 경로를 사용한다. 문자간 배분·탭·마지막 개체 이전 공백의 별도 계약은 유지한다.

방출 시에는 선두 또는 말미 공백의 배분 회수가 필요하면 exact kerning 적용 여부와 무관하게 같은 positions를 게시한다. exact pair가 없는 fallback에서도 회수 결과를 버리지 않는다. 이 묶음은 Frame의 PUA 폭을 전역 재해석하지 않으며 단계1117의 공개 경계 수정은 유지한다.

## 검증 순서와 한계

새 devel의 배경 처리 회귀와 기존 집중 검사·진단 후보를 함께 실행하고 11문서245쪽 및 독립 Print6쪽의 Native TSV·영향 review를 산출한다. 그 뒤 fresh WASM과 새 base 대조를 진행한다. 새 공식 fixture·회귀 추가와 기존 합성 검사 기대값 변경은 관련 Native/fresh WASM 시각 선행 조건을 충족한 뒤 수행한다. 현재 후보는 ignored 실행 증적과 review worktree에만 있으며 정식 회귀 추가로 보고하지 않는다. 남은 HWP3 19쪽·HWPX25쪽과 tracked4쪽 하락은 별도로 해소해야 한다.

초기 묶음에서 fmt와 새 base 기준 unit-tier는 통과했지만 컴파일이 E0061로 실패했다. 리베이스에서 분리된 머리말·꼬리말의 배경 수집 호출에 새 인수 두 개를 전달하지 않은 통합 누락이다. 본문·셀·머리말/꼬리말의 전체 호출을 다시 확인하고, 실제 bin_data와 진입 시점의 배경 삽입 위치를 전달하도록 보정했다. 이 결과는 렌더링 결함의 수정 전 FAIL로 세지 않으며 같은 승인 범위의 검증을 다시 실행한다.
