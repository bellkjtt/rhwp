# #7642 Stage 166 — DYAD 최종 윤곽 표시의 관계 검사

## 독립 근거와 선행 조건

Stage 165의 같은 공개 원본과 한컴 2020 Print를 Native/fresh WASM으로 각각
전체 1쪽 비교했다. 원본 최저 98.50470%, 최소 대조군 99.17678%이며 큰 보기
예약 높이와 본문 간격을 확대 판독했다. 소스는 `c7472832df262ec48c639f35b29301ad9365c4a8`다.
새 저장 예약 영역 검사는 수정 후 실제 nextest PASS, 수정 전 같은 검사 실행은 진행 중이다.

기존 `issue_7593_print_placement`의 두 검사는 SVG `<text>`로 AB를 찾고
`<line>`으로 장식 폭을 찾는다. 현재 공개 윤곽 글리프와 장식은 `<path>`로
표시되므로 요소 이름에 의존하는 검사를 재검토한다. 실제 배치 결함과 표시
요소 종류의 변경을 구분하고, 새 이름의 검사로 독립 Print의 의미를 보존한다.

## 검사 항목과 출력 경로

- RenderTree의 수식 script·셀/문단 소유로 실제 대상을 선택한다. 고정 px 영역으로
  선택하지 않는다. 측정 트리의 실제 문자 순서·정체와 출력 보존을 함께 확인한다.
- 실제 최종 Print SVG를 usvg로 읽어 조상 변환이 적용된 표시 윤곽을 대조한다.
  대상 수식의 점유 상자와 실제 경로의 포함 관계로 내용을 찾아, 발문/보기의
  같은 BaseUnit은 다른 예약 폭에서도 같은 paint 폭인지 검사한다.
- 보기 ㄴ의 표시 잉크는 뒤 본문보다 위에 있어야 하며 수식→본문이 겹치지
  않아야 한다. 기존 저장 예약 영역·기준선 비율의 새 검사는 별도로 유지한다.
- 두 기존 검사는 새 함수명과 파일로 이관한다. 나머지 소유·탭·관계 기호 검사는
  유지한다. SVG 해시·절대 px 위치·새 골든 완화로 실패를 숨기지 않는다.
- 하나의 공용 target에서 수정 전 검사가 끝난 뒤 새 검사 묶음을 한 번에 실행한다.
  최종 전체 회귀·Native/WASM·lint·최신 devel 동기화와 PR은 아직 남아 있다.

## 결과

아직 새 윤곽 관계 검사 실행은 완료되지 않았다. Stage 165 Native/fresh WASM
증거는 표시 구현이 같을 때의 근거이며, 새 코드 변경의 결과로 재사용하지 않는다.
