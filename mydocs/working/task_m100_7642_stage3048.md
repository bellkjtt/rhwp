# #7642 겹치는 병합 제약의 해결 순서와 조각별 물리 공간

Issue: #7642. 수정 전 소스는 `dcbd4c7deee5addb838fd614bcbf30f3c0d792ee`다.

## 독립 근거와 원인

stage3045는 #7028의 10행 2행 병합 칸 요구가 텍스트 48~65.333333px,
패딩 포함 51.733333~69.066667px인데 이미 배분된 행 합이 139.746667px임을
확인했다. 선언은 105.866667px다. 글꼴이나 실제 텍스트 증가가 원인이 아니다.
stage3035의 원본 선언만 재생한 기존 solver도 같은 3.733333/136.013333px를
10/11행에 배정한다. 6~10행 긴 제약이 10행을 채운 뒤, 10~11행 짧은 제약을
다시 확인하지 않고 11~17행 긴 제약이 11행을 먼저 채우기 때문이다.

stage3047의 별도 HWPX를 원문 그대로 한컴2020 11.0.0.9136 Print method0으로
출력했다. 4행/2행/3행 병합이 겹치는 문서에서 Print의 5행 시작은 359.770779px,
6행은 439.727445px다. 기존 Native는 각각 약 380/460px에 놓으며 전쪽 raw는
whole 71.18939%, split 34.95798%다. 이 문서는 수동 합성 입력이고 독립 Print로
관측한 반례이며, 아직 정식 회귀 fixture로 승격하지 않는다.

원본 Print 2쪽도 짧은 병합 칸이 165.579→271.383px, 다음 칸 98.293px,
그다음 칸 117.471px이고 마지막 연관 행은 138.089px다. 큰 높이를 앞 행에서
잘라 없애는 것이 아니라 겹친 제약을 해결하고 실제 남은 공간을 끝 행에 예약해야 한다.

## 생산과 소비 경로

`solve_rowspan_row_heights`의 선언 제약 결과 → HeightMeasurer/레이아웃 행 합 →
앞 조각 `accepted_straddle_fragment_units` → 다음 조각 `straddle_page_band_relief`의
공통 행 높이 → scan 예산과 `table_partial` paint다. solver는 한 미지 행을 실제로
채웠으면 짧은 제약부터 재검토한다. 이미 확정된 제약의 부족분을 마지막 행에
더하는 기존 순서는 보존하며, 선언을 줄여 맞추지 않는다.

조각에서 앞 행의 실제 점유가 달라지면 같은 칸들의 다음 종료 행 요구도 다시
계산한다. 일반 단일행 칸이 없는 행도 같은 물리 공간을 소유하며, 앞에서 끝난
칸과 아직 계속되는 칸의 요구는 최댓값으로 결합한다. 같은 행의 공간을 두 번
합산하지 않는다. 마지막 내용을 소비한 행의 빈 재조판 꼬리는 일반 행 커서로
반복하지 않고, 계속되는 병합 칸의 실제 원장을 통해 남은 행에 예약한다.

## 검증과 경계

작은 whole/split 입력과 원본 6쪽을 먼저 대조한다. 한 조각에서 여러 병합 칸이
끝나는 경우, 일반 칸이 없는 종료 행, 이미 소비한 내용 뒤의 실제 빈 공간,
큰 최소 높이·저장 프레임·블록 컷·뒤 문단을 확인한다. 원본 단위/내용 관계를
보존하고 문서 ID·특정 행·고정 px로 분기하지 않는다.

#7685의 기존 공통 solver 사례와 현재 보정 53쪽, #7969 대조군도 보존한다.
Native/fresh WASM 전쪽 90%·쪽수·확대 판독과 base 대비 하락 검토 전에는
회귀 기대값이나 golden을 바꾸지 않는다. 작은 대조군의 90% 통과로 원본의
미달을 대신하지 않는다. stage3013의 후퇴 후보와 rollback 증거는 보존한다.
