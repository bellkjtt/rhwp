# 이슈 #7642 Stage 47 — 합·근호·복합 분수의 실제 수학 간격

Issue: #7642

## 기준과 실패 증거

시작 source는 `940c1802fc3484212b319d236a9f9c487c62a668`, 정책 base는
`79abd9e49675f4286eaed38197f7e837afb744e7`이다. 전체 55문서·853쪽 Native TSV는
이 source의 고정 바이너리로 문서 세 개씩 실행 중이며 fresh WASM·회귀는 미완료다.
알려진 다섯 쪽수 실패를 해결했지만 9/8/7 HWPX 10쪽 미주 7 수식 영역은
같은 독립 Print와의 2px 내용 실루엣 보조값이 86.02059%다. 페이지 96.43106%로
이를 면제하지 않으며 회귀 기대값을 바꾸지 않는다.

## 독립 메트릭과 원인 후보

원본의 첫 합·분수 수식은 BaseUnit 900 HU, 선언 폭 8391 HU다. 현재 Native의
내용 프레임 폭은 111.9지만 마지막 숫자 원점이 프레임 안에서 이미 113.07이다.
전체 수식을 선언 프레임에 가로 압축하면 실제 간격 문제를 숨기므로 사용하지 않는다.

Print의 PDFium 글자 객체는 원시 font size와 변환 matrix를 함께 소비한다.
이 PDF의 scale 0.12에서 75/51/135는 실제 9/6.12/16.2pt다. 따라서 첨자 0.68배는
정상이며 이 비율을 폭 차이의 원인으로 바꾸지 않는다. 실제 합 기호와 아래 첨자의
원점도 Native와 거의 일치한다. 첫 분수 괘선은 Print x=421.92이고, Native의
합 첨자 점유 끝에서 그 위치까지의 간격은 약 0.10em이다.

`BIG_OP_TRAIL_PAD=0.45`의 설명은 기존 `scale_x`가 자연 폭과 여백을 압축한다는
가정에 의존한다. 현재 `svg.rs`는 자연 가로 폭을 보존하므로 그 가정이 남은
예약 값을 정당화하지 못한다. 분수·근호의 내부 여백과 연산자 양쪽 간격도 같이
추적해 하나의 사유로 모두 축소하지 않는다.

ignored `stage47-native-equation-frame-and-glyphs.json`에는 원본 소유와 같은
SVG group의 실제 글자 원점, `stage47-print-equation-glyph-positions.json`에는
독립 PDF 객체의 글꼴·변환·원점이 있다. 공개 Latin Modern Math 글리프 메타데이터와
설치된 한컴 글꼴의 메타데이터도 분리해 읽었다. 한컴 글꼴 바이트·윤곽은 새 증적이나
Git에 포함하지 않는다.

## 묶음 분석·수정·검증 계획

1. 같은 합·복합 분수와 합 없는 분수·근호·단순 숫자 분수를 여러 BaseUnit으로
   정상 한컴 저장·Print 출력해 실제 논리 전진과 간격을 확인한다. MCP canonical
   `start → status → download`, 명시적 2024 engine을 사용하며 원본 PDF를 대체하지 않는다.
2. 큰 연산자의 첨자 점유 끝 → 다음 피연산자 원점, 분수의 자식 점유 → 괘선 여백,
   근호의 몸체 원점 → 다음 연산자 간격을 연결한다. 저장 폭·문서 ID·고정 px 좌표로
   분기를 만들지 않는다. 실제 글꼴·수학 구조의 공통 결과를 측정과 SVG/Canvas에 전달한다.
3. 근거가 모인 관련 수정을 묶어서 빌드한다. 원본 미주 7의 같은 영역·앞뒤 문단,
   정상 단순 분수·합·근호와 요청 corpus의 영향 페이지를 비교한다. 실패 영역의
   90% 이상과 직접 판독을 확인한 뒤 fresh WASM·전체 TSV를 실행한다.
4. 관련 입력의 모든 페이지·출력 경로가 90% 이상이고 확대 판독도 충족하면 #1139
   전체와 관련 회귀를 소유·순서·보존·포함·겹침 관계로 변경한다. 원래 55문서 검증과
   전체 회귀·필수 lint·PR/CI·trailing·머지·후속 처리는 계속 남아 있다.

TSV·JSON·실행 로그·nextrun은 ignored output에 보존하고 Git에 커밋하지 않는다.
