# #7642 Stage 87 — 대문자 변수의 표시 face와 기울임 계약

Issue: #7642

## 독립 근거

크기별 NOT의 W와 9월 2024 HWPX Print 스트림을 직접 읽었다.
기본 이탤릭 대문자 A/B/C/D/E/F/R/S/W/X/Y/Z의 수학 PUA는 모두
`Tm=[1,0,0.333,-1,...]`로 표시된다. 소문자 수학 PUA는 같은 스트림에서
shear가 0이다. bfchar와 bfrange를 모두 해석했으며 미해석 CID는 없다.
결과는 ignored output의 `stage86-print-variable-transform-audit.json`에
PDF 해시·페이지·문자·실제 변환과 함께 보존했다.

현재 표시 투영은 대문자도 Latin Modern Math의 Unicode 수학 이탤릭
글리프를 직접 선택한다. 이것은 원본의 정체 글리프에 적용한 기울임과
글리프 설계·잉크 범위가 다르다. 공개 정체 W의 윤곽을 원본의 em 잉크
프레임과 독립 Print shear에 배치한 SVG 진단은 모양이 Print에 가까워졌다.
진단은 production 출력의 통과가 아니며, W 하나의 코드 예외로 구현하지 않는다.

## 후보와 검증 범위

- 한컴 수학 face의 보통 굵기 이탤릭 ASCII 대문자 전체에 동일한 표시 계약을
  적용하는 후보를 검토한다. 정체·굵은 변수·소문자·다른 face는 같은 근거가
  없는 방식으로 바꾸지 않는다.
- 공개 Latin Modern Math의 A~Z 정체 윤곽만 라이선스와 출처를 보존해 사용한다.
  설치 HYhwpEQ에서는 em 잉크 프레임의 메트릭만 읽고 사설 바이트·윤곽을
  코드·자산에 복제하지 않는다. 공개 파생 asset의 이름과 manifest를 구분한다.
- 논리 전진·기준선·AST와 줄 소속을 유지한다. 실제 표시 윤곽은 공통 FontGlyph
  결과로 발행해 SVG·Canvas·Skia·paint JSON·CanvasKit이 소비하게 한다.
  NOT는 변수 역할을 보존하며 기울임을 두 번 적용하지 않는다.
- 6/9/12/18pt의 A~Z와 소문자·정체·굵은 변수 대조군을 한컴 2024 MCP에서
  정상 저장하고 저장본을 Print 출력한다. 수동 변경 입력의 오래된 선언 상자와
  정상 저장본의 재생성 상자를 구분한다. 정상 저장본이 독립 기준의 입력이다.
- 대조군·기존 NOT·실물 영향 쪽의 Native/fresh WASM Visual Sweep과 확대 판독
  뒤 후보를 판정한다. 진단 PNG의 높은 점수를 실제 구현 통과로 승격하지 않는다.
  90% 미만인 입력의 기대값·baseline·정식 회귀는 변경하지 않는다.

## 현재 상태

공통 원인의 독립 스트림 근거와 공개 윤곽의 W 진단을 확보했다.
전체 대문자의 독립 대조군·후보 코드·Native/fresh WASM 실행은 아직 미완료다.
Stage 86의 미주 경계 source 검증도 고정 바이너리와 package에서 별도로 계속한다.

## 후보 적용

공개 A~Z 정체 윤곽만 포함하고 이름을 변경한 5,236 byte subset과 manifest를
추가했다. `uppercase_outline`은 모든 ASCII 대문자에 같은 em 프레임·Print
기울임·인쇄 원점을 적용한다. `source_font_text`의 보통 굵기 이탤릭 경로가
이 결과를 FontGlyph로 발행하며 기존 논리 전진·높이·기준선은 보존한다.
정체·소문자·굵은 변수·다른 face는 기존 경로를 따른다. NOT도 대문자 변수의
역할을 유지해 사선 기하가 FontGlyph 전환으로 달라지지 않도록 했다.

6/9/12/18pt 전체 A~Z, 소문자, 정체·이탤릭·굵은 변수 대조군을 한컴 2024
13.0.0.3901에서 정상 저장했다. save job은
`bd3a4a38-6c33-4ef3-9c1c-db97bec4feb8`, Print job은
`3588cad0-8395-466f-b3cd-d0b83a6dbf5c`다. Print method 0과
`frame_print_to_pdf_ex_one_up`, 전체 1쪽을 실제 status에서 확인했다.
생성 입력의 캐시는 비웠으며 정상 저장본을 독립 비교 입력으로 사용한다.
자료는 ignored `stage87-uppercase-frame-probe/`에 보존한다.

Stage 86 전용 controller는 WASM 시작 전에 종료됐으므로 별도 WASM 완료로
판정하지 않는다. 같은 후보 빌드에 두 보정을 포함해 원본 20~22쪽, 변수 대조군과
기존 경계를 함께 검증한다. 현재는 후보 적용 상태이며 정식 회귀·기대값은
변경하지 않았다. Native/fresh WASM 실행과 전체 원본 검증은 미완료다.

## 연속 글자의 간격 반례

같은 정상 저장본의 변경 전 Native 300dpi 전체 한 쪽은 50.02850%다.
대문자 윤곽만의 문제로 분류하지 않는다. 소문자 대조군도 글자 원점의 간격이
다르며, 앞뒤 본문은 올바른 저장 수식 프레임의 끝에 놓여 있다.
`~`를 포함한 정상 저장 A~...~M의 논리 폭은 6pt에서 8925 HWPUNIT,
18pt에서 27000 HWPUNIT다. 기존 한컴 글자 전진 합에 **반 em**을 12번 예약하면
그 저장 폭과 일치한다. 이 값은 진단 관측이며 화면 좌표 기대값이 아니다.
Print의 18pt A→B 원점 차이 약 30.06은 독립 A 전진 18과 반 em 12에
해당한다. 6pt A→B도 약 10.07로 같은 계약을 확인했다.

기존 `SpaceKind::Normal`은 한컴에서도 일반 TeX의 0.33em을 사용해
실제 글자가 선언 프레임보다 좁게 표시됐다. 한컴 face의 명시 `~`만 같은
반 em 결과를 측정·배치에 사용하도록 보정하고, 검증된 Normal 공백을
누락 캐시 재발행의 지원 구조에도 포함한다. 다른 face의 기존 공백과 Thin은
바꾸지 않는다. 대문자와 소문자·정체·굵은 변수의 같은 간격 반례를 함께
비교하며 이 미달 입력을 정식 회귀로 추가하지 않는다.

첫 후보 `af68ac05c`의 Native 빌드는 FontGlyph의 정적 문자열 필드에
String을 전달한 타입 오류(E0308)로 실패했다. 기존 필드의 문자열 참조
계약에 맞춰 수정하고 같은 빌드·집중 검증을 재실행한다. 이 빌드 실패를
렌더링 결함의 수정 전 FAIL이나 시각 회귀 재현으로 세지 않는다.
