# #7642 서명과 꼬리말의 잔여 가로 차이 분석

Issue: #7642

## 현재까지 확인한 결과

`330db0e2daf0ad9892873ee0f58b4a3c624ce990`의 #1950 원본은 기존 Print와 새
2020 MCP Print 모두 1쪽, Native raw 99.82699%다. 관련 Rust 12건은 모두 통과했고,
동일 진단 코드의 고정 줄간격 계약은 수정 전 다섯 줄 불일치(exit 3)에서 수정 후
다섯 줄 모두 일치(exit 0)로 바뀌었다. 이는 전체 PR 완료 판정이 아니다.

새 전체·하단 review와 standalone overlay를 직접 열었고 사용자가 지적한 서명의
`(인)`과 꼬리말 `- 581-35 -`의 가로 차이는 남아 있다. 이 차이를 페이지 점수로
면제하거나 좌표 이동으로 숨기지 않는다. 대기 중이던 fresh WASM 빌드는 실제
Cargo 실행 전에 취소하고 이 두 원인을 함께 보정한 뒤 새로 검증한다.

## 서명: 원본 언어 슬롯의 자간이 다르다

원본 글자모양 24는 한글 자간 -5%, 영문 자간 0%다. 독립 한컴 HWP 저장본의
대응 글자모양 12에서도 같은 배열을 확인했다. 장평은 두 슬롯 모두 100%다.
현재 한글 run 전체가 공백과 괄호까지 -5%로 측정되므로, 21개 공백이 누적되면서
`(` 원점이 Native 585.70667px, 원본 Print 592.15906px로 벌어진다(96dpi 진단).

원본 Print의 `집/행/관` 원점 간격은 약12.633px로 한글의 -5%와 대응한다.
괄호는 한양신명조 HFT의 고유 폭 395/1000·374/1000과 영문 자간0%에 대응한다.
같은 글꼴 이름이라는 이유로 언어 슬롯의 장평·상대 크기·자간까지 같다고 판단하면 안 된다.
HFT 공백의 자간을 무조건 없애는 변경은 하지 않는다. 별도 동등 슬롯 표본을 대조한다.

## 꼬리말: 미확인 대체 프로그램 폭이 정렬을 오염시킨다

원본은 영문 `HCI Tulip`을 선언한다. 기존 코드는 숫자의 고유 폭498/1000만 알고
하이픈은 표시용 `HY견명조`의 폭으로 재므로 10pt에서9.44px로 전진한다.
원본 Print Type3 T3의 하이픈 고유 폭은332/1000이다. 표 가운데 정렬도 이 잘못된
전체 폭을 소비해 첫 하이픈의 원점까지 이동한다. 마지막 하이픈은 다른 중립 run의
글꼴을 상속하므로 글꼴 슬롯과 최종 paint의 출처도 함께 대조한다.

대상 PDF에서 좌표를 복사해 맞추지 않고 독립 ASCII95자·크기·굵기 표본을 한컴
2020에서 정상 저장한 뒤 Print로 출력해 고유 폭을 확인한다. 일반 공백과 고정폭
빈칸 U+2007의 차이도 유지한다.

## 실제 소비 경로와 다음 검증

원본 언어별 속성 → style resolver → composer의 문자 슬롯/줄 구성 → 공통 문자
폭·위치 → 정렬의 전체 폭 → TextRun과 Native/Canvas paint의 순서로 추적한다.
공통 helper 이후 다른 글꼴·자간·좌표가 덮어써지는 경로도 확인한다. 해당 원본의
Native/fresh WASM 전쪽 TSV·직접 확대 판독, 정상 대조군과 회귀를 통과하기 전에는
새 정상 golden·완료 판정을 추가하지 않는다.

진단 로그·원점·원본 속성은 ignored `stage3903-signature-footer-position-trace/`,
독립 문자 표본과 MCP job은 `stage3904-independent-latin-space-specimen/`에 보존한다.
실행 증적의 상위 경로는 `output/pr-review/issue7642/failed-inputs-20261008/stage15-current-validation/`이다.

## 보정 후보 구현

중립 문자의 슬롯 선택 helper를 composer의 실제 run 분할과 줄 채움의
`ParagraphMetricScope`, 끝 자간 계산이 함께 사용한다. 영문에 명시한 자간·장평·
상대 크기가 상속 슬롯과 다르면 해당 ASCII 공백·구두점은 영문 슬롯을 사용한다.
같은 속성의 기존 공백은 유지하고, 뒤 한글의 상속 언어·원문 문자 순서를 바꾸지 않는다.
문서명·좌표·공백 개수를 구현 조건으로 쓰지 않는다.

`HCI Tulip`은 독립 Print로 확인한 하이픈332/1000과 기존 숫자498/1000을
공통 FontMetric에 등록했다. 숫자만 별도 계산하고 나머지를 무조건 표시용 글꼴로
보내던 분기를 제거했다. 구두점의 영문 프로그램 여부도 표시용 치환 face가 아니라
검증한 원본 metric face로 판단한다. 아직 확인하지 않은 문자는 원래 표시 프로그램의
메트릭으로 넘긴다. 별도 ASCII95자·굵기 표본은 이 부분 표의 독립 재확인용이며 결과를
받기 전에 전체 ASCII 프로그램의 검증을 완료했다고 주장하지 않는다.

새 원본 슬롯 계약 진단(`stage3907-independent-neutral-slot-contract/`)은 수정 전
서명에서 공백·괄호 23개 모두 원본 영문 자간과 불일치하여 의도한 exit 3을 냈다.
수정 전 생산자는 `330db0e2da`이며 진단 자체의 빌드 성공과 실행 실패를 분리했다.
