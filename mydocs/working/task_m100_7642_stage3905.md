## 서명: 원본 언어 슬롯의 자간이 다르다

원본 글자모양 24는 한글 자간 -5%, 영문 자간 0%다. 독립 한컴 HWP 저장본의
대응 글자모양 12에서도 같은 배열을 확인했다. 장평은 두 슬롯 모두 100%다.
현재 한글 run 전체가 공백과 괄호까지 -5%로 측정되므로, 21개 공백이 누적되면서
`(` 원점이 Native 585.70667px, 원본 Print 592.15906px로 벌어진다(96dpi 진단).

원본 Print의 `집/행/관` 원점 간격은 약12.633px로 한글의 -5%와 대응한다.
괄호는 한양신명조 HFT의 고유 폭 395/1000·374/1000과 영문 자간0%에 대응한다.

## 꼬리말: 미확인 대체 프로그램 폭이 정렬을 오염시킨다

원본은 영문 `HCI Tulip`을 선언한다. 기존 코드는 숫자의 고유 폭498/1000만 알고

글꼴을 상속하므로 글꼴 슬롯과 최종 paint의 출처도 함께 대조한다.

이 페이지는 여전히 시각 완료가 아니다. 실제 차이는 선언 글꼴·항목 간격, 범례와 막대의

원본 차트 XML → 파서의 계열·범례 속성 → OOXML 모델 →
`renderer::render_chart_svg`의 플롯 예약 → `legend_items`·`render_legend` →
`shape_layout`의 RawSvg → Native/Canvas 소비 경로로 추적했다. 원본은 HWPX chart
선택지와 OLE 대조 자료를 함께 갖는다. 파서가 데이터 라벨의 `noFill`을 계열 자체의
테두리 없음으로 승격하는 것을 확인했다. 정확한 `ser/spPr/ln`, 축선·격자선의 소유 경로와
선언 글꼴을 분리해 소비하는 공통 후보를 작성했다. 범례의 실제 선언 글꼴 측정 결과를
공간 예약·표시에 함께 공급하고, 두 원본 차트와 기존 우측 범례 대조군을
독립 Print 및 Native/fresh WASM으로 재검증한다. 문서명·페이지·화면 좌표를 분기 조건으로
쓰지 않는다.

  26·27쪽 전체 페이지 일치율은 각각 94.21168%, 94.23268%다. 27쪽의 기존 값은
  91.56789%였다. `stage3957`에서 원본 27쪽의 같은 영역 review·standalone overlay를

  제목·범례 위치·색 차이는 남아 있으므로 완료 판정하지 않는다.
- `stage3951`은 빌드 도중 범례 후보가 바뀌어 소스 해시 검사가 실패했다. 컴파일 exit 0을

  변경하지 않았다. 데이터 라벨의 선이 계열 기본값에 남는 경우도 초기화한 뒤 정확한 경로로

## 저장 계열 식별자와 범례 색의 독립 Print 검증

`0349c6e0c5c094da972875da81a45d06882d04cc`의 `stage3963` Native 전쪽 재검증은
14문서·301쪽 모두90% 이상, 쪽수 일치이며 전체 최저93.37061%다. PrEP140쪽 최저는

`stage3962`에서 정상 번호의 폭 대조군도 직접 출력했다. 두 쪽은90.34941%·86.46953%로,
둘째 쪽의 범례·플롯 배치는 여전히 보정 대상이다. 원본27쪽94.23268%와 합산하지 않는다.

색 대응은 저장 식별자와 표시 순서를 나누어 추적했다. 여성 차트의 `c:idx`는
`5,0,4,1,2,3`, `c:order`는 `0,1,2,3,4,5`다. `stage3971` 대조군은 둘째 차트의 idx만
`0,1,2,3,4,5`로 바꾸고 이름·값·순서·면색·OLE fallback을 유지했다. 한컴2024
13.0.0.3901, PrintMethod0, `frame_print_to_pdf_ex_one_up`, job
`4f0c0640-c476-425e-92da-5c34ddd96919`의 독립 Print에서 첫 막대의 RGB는 양쪽
`39,161,114`로 같지만 첫 범례 키는 보라에서 파랑으로 바뀌었다. 범례가 표시 순서의
현재 면색 대신 저장 idx의 기본 팔레트를 소비함을 분리해서 확인했다.

원본 Print의 고해상도 차트 bitmap에서 idx5 범례 키의 최빈 RGB는
`163,92,194`(`A35CC2`)다. 이전 여섯째 색은 측정 없이 추정한 하늘색이었다.
저장 idx를 모델에 보존하고, 위 한컴 사용자 서식(`colorIndex=-1`)과 명시 idx가 있는
범례에서 해당 색을 소비하게 했다. 일반 범례와 식별자 없는 모델은 기존 면색 경로를 유지한다.
원본 채움·값·계열 표시 순서·미리보기 색 복원 경로는 바꾸지 않는다. 아직 입증하지 않은
전체 accent 테마 해소는 후보에 포함하지 않았다. `stage3975`의 기존 차트 검사165개는
모두 통과했다. 이 후속 코드의 Native/fresh WASM 시각 검증은 별도로 계속한다.

`stage3966`에서 차트 XML 제목만 바꾸는 대조 Print도 확인했다. 제목 영역이 변했으므로
