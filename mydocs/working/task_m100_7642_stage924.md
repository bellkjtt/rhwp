# 단계 924 같은 쪽 단 밴드의 구역 간격 소비

Issue: #7642. HWPML 3쪽의 Native/fresh WASM 74.65508%/74.54315%는 미달이다. 원본 ViewText를 읽어 구역 정의의 `column_spacing=1134HU`, 제목·본문의 별도 단 정의를 확인했다. 파일 형식 정본 표 129는 이 값을 “동일한 페이지에서 서로 다른 단 사이의 간격”으로 정의한다. `shortcut.hwp`의 같은 필드는 2000HU이므로 문서별 수치를 새 조건으로 고정하지 않는다. 원본 파일은 바꾸지 않는다.

독립 수동 Print 3쪽의 텍스트 원시 CTM/Tm을 원본 단위로 대조하면 제목까지 약 69HU, 첫 목차까지 약 132HU의 차이가 누적된다. 기존 1200HU와 원본 1134HU의 차이 66HU가 두 단 전환에서 더해진 경로와 일치한다. 이는 Print 드라이버의 미세 배율·정수 격자와 구분하며, 점수를 위해 PDF나 PNG를 이동하지 않는다.

생산은 `SectionDef.column_spacing`이고 `document_core/queries/rendering.rs`가 TypesetEngine과 LayoutEngine에 같은 값을 이미 전달한다. 셀의 단 밴드 흐름은 이를 소비하지만 본문 `typeset/section/columns.rs`와 `layout.rs`의 단 전환 fallback은 공통 `solo_zone_pad_px`의 상수만 사용했다. 해당 helper가 원본 단일 단에서 다음 단일 단으로 넘어갈 때 전달받은 구역 간격을 사용하도록 수정한다. 이미 별도 근거를 사용하는 표 헤더·다단 밴드의 경로는 이 fallback에 들어오지 않는다. 구역 정보가 없는 합성/직접 호출은 기존 fallback을 유지한다.

현재 전체 회귀는 수정 전 후보를 검증 중이며 이 수정의 통과 증거가 아니다. 빌드 후 HWPML 영향 쪽·전체 122쪽과 shortcut의 독립 Print 대조, Native/fresh WASM 전체·최신 base 하락 검사·필수 lint 및 회귀를 확인한다. 실물 문서의 새 회귀 추가는 해당 문서 전체 시각 gate가 통과한 뒤 수행한다.

전체 회귀에서 기존 `test_svg_text_ratio`가 같은 sqrt 오인을 원시 SVG 문자열로 고정하고 있어 실패했다. 이미 독립 Print·전쪽 Native/fresh WASM·직접 판독을 마친 #5821의 계약에 따라 새 이름의 SVG 검사로 교체한다. 실제 출력 XML에서 원본 선언 크기와 가로/세로 배율 관계, 두 글자의 보존을 검사하며 화면의 고정 좌표나 특정 font-size 문자열을 비교하지 않는다. 이 단위 검사를 실제 HWPML 전체 통과 증거로 사용하지 않는다.

같은 전체 실행의 #4969 glyph lowering 검사도 sqrt 장평으로 산출한 로컬 px 배열·글꼴 크기를 고정하고 있었다. 새 이름으로 선언 스타일의 세로 크기와 가로 장평, 독립적인 page 좌표와 local→page 역변환 관계를 확인한다. 원본 glyph ID·cluster 범위·실제 shaping 측정값·resource 보존 검사는 유지한다. 두 장평 검사 외에 검출된 실물 문서의 소유·쪽수·위치 실패는 입력별 Print/시각 검증 후 원인을 나누어 처리하며 허용치를 완화하지 않는다.
