# #7642 중간공한 HFT의 공통 전진폭 보완 계획

## 입력과 독립 기준

`samples/hwp3-sample4-hwp5.hwp`의 글자 모양 6은 16pt·장평 100%·굵게이며
한글 face 3은 HFT `중간공한`이다. 원본 19쪽 제목의 Print 글자 크기는
PDF 글자 행렬을 적용하면 약 15.94pt다. Type3의 표기 크기 133을 실제 글자 크기로
해석하지 않는다. 원본의 선언 크기를 줄여 맞출 문제가 아니다.

설치본 `/opt/hnc/hoffice11/Shared/Fonts/hftinfo.dat`는 이 family를
`KHANM.HFT` / `KHANENGM.HFT`, 영문명 `Konghan Normal`에 연결한다.
파일도 설치되어 있다. Fontconfig의 `fc-match '중간공한'`은 Noto Sans로 폴백하므로
설치된 HFT 프로그램과 일반 TrueType 글꼴 공급을 같은 상태로 취급하지 않는다.

같은 원본의 글자 모양·face 선언을 로컬 HWPX에 보존한 뒤, 한글 전체 11,172자와
ASCII를 보통·굵게 각각 나열한 독립 진단 입력을 만들었다. 원본 문서를 수정하지 않았다.
MCP에는 `target=pdf`, `engine=2020`만 요청했다. 출력은 한컴 11.0.0.9136,
Print method 0, `hancom2020_pdf_driver_one_up`, 30쪽이다.

보통·굵게 전 11,172자의 폭이 같고 누락·상충은 없다. 원본 19쪽의 해당 Type3 프로그램에
있는 108자 전부가 독립 전체 문자 대조군의 폭과 일치한다. 예를 들어 간=741,
프=598, 예=928/1000em이다. 현재의 일률적인 한글 1em이 올바른 폭이 아니다.

## 공통 결과와 적용 경계

전체 문자 표를 동일 폭 벡터로 분류하면 초성 12군·중성 8군·종성 1군의
96개 값으로 완전히 표현된다. 모든 음절을 원래 11,172개 값과 재대조한 뒤
기존 `HangulMetric`을 사용한다. 문서 번호·페이지·문자열에 따른 분기는 추가하지 않는다.

`legacy_hft::metric_face_name`에서 **HFT로 선언된** `중간공한` / `Konghan Normal`만
프로그램 전용 이름으로 연결한다. 측정 표 등록 → style_resolver의 언어별 원본 metric face →
text_measurement의 공통 문자 전진 walk → 줄 나눔·배치 char positions →
Native/Canvas의 glyph-fit positions 순서로 소비되는지 확인한다.
기존 HFT 굵기 전진과 반각 공백 계약은 별도로 유지하고, 표시용 글꼴을 원본 프로그램으로
확인했다고 주장하지 않는다. 동명의 TTF·다른 HFT·기존 정상 대조군도 보호한다.

## 검증과 제출 상태

이 문서 작성 시점에는 데이터·측정 경로 구현 전이다. 구현 뒤 source를 고정해 관련 집중 Rust,
원본 전 36쪽 Native/fresh WASM·확대 판독과 base 대비 하락 여부를 확인한다.
현재 90% 미만인 원본을 새 정상 golden으로 고정하지 않으며, 이 폭 진단만으로
전체 시각 자격이나 PR 준비 완료를 선언하지 않는다.
