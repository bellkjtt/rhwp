# #7642 Stage 189 — 저장 글줄의 물리 하단과 인라인 도형의 줄 소유

Issue: #7642

## 독립 근거와 원인

Stage 188의 언어 원본 15쪽은 12쪽이 90% 이상이고 2·8·11쪽은 미달이다. 2쪽의 문단 36은 base와 현재 같은 y 403.5에 그려지나 fit 커서는 174.6이다. 단 y 209.8에 대한 실제 문단 원점은 193.7이므로 fit 간격 생략과 실제 글줄 원점 사이에 차이가 있다. source의 줄 vpos 14528·높이 1300·뒤 간격 844 및 문단 뒤 간격 568은 다음 표 원점 17240을 정확히 잇는다. 이 관측은 진단이며 px 회귀 기대값으로 사용하지 않는다. 8·11쪽은 TAC 도형이 글줄을 소유하는데 기존 내용 하단 공유 판정에서 제외된다.

## 구현 주장과 소비 연결

첫 실제 원본 글줄이 단의 0 원점을 소유하고 앞 간격이 없으며, 현재 문단의 구성 줄 높이·간격이 원본과 동일할 때 저장 사다리의 실제 점유 끝을 단 상대 좌표로 기록한다. `format의 구성 메트릭 + 원본 LineSeg + 첫 실제 항목의 source 원점 → stored_content_bottom → paragraph_fragment_content_bottoms → 직전 문단/끝 줄 소유와 원본 상대 gap → StoredTacPlan fit/origin/end → control placement → paint`를 연결한다. 0 원점은 단 좌표의 원점이며 문서별 화면 수치를 추가하지 않는다.

HWP5 저장 조판 계약이 아닌 입력, 편집·dirty·미주, 다른 단 시작 높이/원점, 사다리 리셋 또는 다시 구성한 메트릭은 이 경로로 인증하지 않고 기존 구성 점유 결과를 사용한다. 실제 source 높이·간격이 달라진 줄을 저장값으로 덮지 않는다. 음수 간격에서도 이미 점유한 앞 줄의 하단을 지우지 않는다. 인라인 그림·도형·양식의 treat_as_char 소유도 기존 수식과 함께 같은 텍스트 줄의 하단 공유에 포함한다. 독립 float와 표는 제외한다.

첫 원본 0 좌표는 `LayoutEngine::build_single_column`의 first Full/PartialParagraph 기준축과 같은 계약이다. source가 아닌 순차 커서를 실제 위치로 인증하는 오류를 제거하고, 확정된 하단을 표 계획이 소비해 배치에 전달한다. 정상 HWPX WMF 대조군은 새 HWP5 source 인증에 비해당이며 기존 경로를 재검증한다.

## 검증

원본 언어 전쪽, 정상 대조군, 10월 미달 경계를 같은 Native binary와 독립 Print PDF로 다시 확인한다. Native 전쪽 통과 후 fresh WASM 전쪽 TSV와 확대 확인을 이어간다. 새 회귀와 기대값은 전쪽 Native/fresh WASM 90% 이상과 직접 판독 뒤에만 추가한다. 모든 Cargo는 `/home/tsjang/rhwp/target/pr-review`에서 순차 실행하며 임시 TSV·로그·JSON은 ignored output에 보존한다.

사전 fmt·fmt check·diff check 및 `cargo check --locked --lib --bin rhwp --target-dir /home/tsjang/rhwp/target/pr-review`는 exit 0, check 40.90초다. 실제 source와 같은 줄 메트릭을 인증하는 쪽만 저장 단 좌표를 사용하며, 최종 Native/fresh WASM 결과는 아직 미검증이다.
