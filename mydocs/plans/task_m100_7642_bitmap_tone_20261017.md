# #7642 한컴 2024 Print의 원본색 bitmap 전달 경로 보정

Issue: #7642

## 근거와 적용 범위

독립 Print와 입력 변형 진단은
[stage2025](../working/task_m100_7642_stage2025.md)에 보존했다.
추가 stage2028/2029에서 16비트 BMP·32비트 BMP·16비트 PNG·알파·그림 효과를 한 번에
출력했다. 원본색 bitmap은 픽셀 성분 확장과 같은 방향이며, 그레이스케일·흑백은
같은 처리를 하지 않는다. 밝기·대비를 지정한 경로에서는 효과 뒤 색 변환 순서와
기존 대비식 차이가 남는다. 이를 원본색 경로의 통과로 완료 처리하지 않는다.

우선 시험지의 현재 공통 미달에 해당하는 **밝기·대비 보정 없는 원본색 그림**을 고친다.
문서명·쪽·좌표·그림 크기로 분기하지 않는다. 한컴 2024 Print, BMP/PNG,
원본 RGB 색이 8비트 팔레트 용량인 256개를 초과하는 경우를 사용한다.
2020·화면 프로필·JPEG·팔레트 범위·그레이스케일·흑백·지정한 밝기/대비는 반례로 보존한다.
미검증 경로를 해결했다고 주장하지 않으며, 전체 범위의 미달과 기존 회귀 실패는 계속 보정한다.

## 생산과 소비의 연결

1. `DocumentCore::build_canvas_page_layer_tree_with_profile`의 실제 `hangul2024_compat`와 Print
   프로필을 LayerBuilder에 전달한다. 장치 픽셀 값의 존재로 제품 세대를 추정하지 않는다.
2. LayerBuilder가 ImageNode의 출력 전용 표지를 설정한다. 원본 IR, 그림 크기·crop·좌표·
   줄 구성은 바꾸지 않는다. 표·각주·그룹의 그림도 같은 Image leaf 하위화 경로를 소비한다.
3. image_resolver의 한 변환에서 제한된 디코드·색 수 확인·RGB 성분 확장·PNG를 만든다.
   같은 변환을 Native Skia, Canvas/SVG의 resolved payload가 사용한다.
4. `SourceImageVariant`에 별도 출력 신원을 두고, inline JSON·바이트 생략 후 재조회가
   같은 변환을 사용하도록 연결한다. 2020/2024 및 화면/Print의 캐시를 섞지 않는다.
5. 직접 구성한 `PaintOp::Image { resolved: None }`의 fallback도 같은 결과를 사용한다.
   이미 변환된 payload를 재생할 때 표지를 지워 성분 확장을 중복 적용하지 않는다.

## 검증 순서와 완료 조건

새 Native/fresh WASM으로 같은 원본의 전쪽 TSV를 산출한다. 11월 공통 실패 문서와
10월 입력, 원본·정상 저장 sample16 및 독립 색 수/형식 대조군을 묶어 확인한다.
현재 제품 원본과 입력 변형 진단을 구분하고, review와 standalone overlay를 함께 직접 연다.
새 회귀는 해당 원본·관련 모든 페이지의 양쪽 90%와 확대 판독 이후에만 추가한다.
기존 golden과 허용치는 바꾸지 않는다. source SHA·새 빌드·로그·입력·Print 해시를 기록한다.
최신 devel 대비 하락, 원래 12개 회귀 실패와 전체 Rust/lint는 별도 필수 gate로 남는다.
